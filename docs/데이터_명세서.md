## 2. 환경공단 충전기 상태 (직접 수집)

- **출처**: 공공데이터포털 「한국환경공단_전기자동차 충전소 정보」 `getChargerInfo` (제주 `zcode=50`)
- **수집 방법**: `collect.py`가 30분마다 전체 목록을 받아 저장 → 오라클 클라우드 무료 서버에서 실행하고 이 저장소에 올림
  - 수집 초기(11/4~11/5)에는 GitHub Actions(`.github/workflows/collect.yml`)로 돌렸습니다.
- **인증키**: 환경변수 `KECO_KEY` (저장소에는 없음)

### 2-1. 파일 4종

| 파일 | 내용 | 대상 | 주기 |
|---|---|---|---|
| `data/status/YYYY-MM-DD.csv.gz` | 상태 기록 (하루 1파일, 30분마다 덧붙임) | **급속 전체 + 공공기관 완속** | 30분 |
| `data/latest.csv.gz` | 가장 최근 상태 1회분 (화면의 '지금 상태') | 위와 같음 | 30분 |
| `data/master/YYYY-MM-DD.csv.gz` | 충전기 기본 정보 (이름·위치·종류 등) | 제주 전체 | 하루 1번 |
| `data/master_full/YYYY-MM-DD.csv.gz` | API가 주는 모든 항목 (설치년도·제조사 등) | 제주 전체 | 하루 1번 |

> 상태 기록은 급속 충전기 전체와 공공기관(JD·ME·JC·JE·JT) 완속 충전기만 남깁니다. 민간 완속은 기본 정보(`master`)에만 있습니다. 완속은 충전기 종류 코드 `02`, `08`입니다.

### 2-2. 상태 기록 항목 (`status`, `latest`)

| 항목 | 뜻 | 예시 | 진단에서 쓰임 |
|---|---|---|---|
| `collected_at` | 수집 시각 (한국 시간) | `2026-11-04 16:12` | 시간 순서, 상태 지속 시간 |
| `statId` | 충전소 ID | `ME174046` | 충전기 식별 (충전소 ID + 충전기 ID) |
| `chgerId` | 충전기 ID (충전소 안 번호) | `01` | 〃 |
| `busiId` | 운영기관 코드 | `ME` | 공공 충전기 구분, 운영사별 화면 |
| `stat` | 충전기 상태 코드 (아래 표) | `2` | 공식 상태 판정(A) |
| `statUpdDt` | 상태가 마지막으로 바뀐 시각 | `20261104155938` | **며칠째 그 상태인지** 계산 |
| `lastTsdt` | 마지막 충전 시작 시각 | `20261103201123` | 충전 세션 복원, **마지막 이용 시각** |
| `lastTedt` | 마지막 충전 종료 시각 | `20261103204209` | 충전 길이 → 5분 미만 실패 충전(B3) |
| `nowTsdt` | 지금 충전이 시작된 시각 | (충전 중일 때만) | 충전고착(A4) |

`statUpdDt`와 `lastTsdt` 덕분에 수집을 시작하기 **훨씬 전부터의 방치 기간**도 계산할 수 있습니다. 예를 들어 1년 전에 마지막으로 충전된 충전기는 첫 수집 때부터 바로 '1년 넘게 미사용'으로 잡힙니다.

**상태 코드 `stat`**

| 코드 | 뜻 | 진단 분류 |
|---|---|---|
| 1 | 통신이상 | 통신 오류 (A2·A3) |
| 2 | 충전대기 (사용 가능) | 정상 → 숨은 고장 검사 대상 (B) |
| 3 | 충전중 | 정상 / 오래 이어지면 충전고착 (A4) |
| 4 | 운영중지 | 운영불가 (A1) |
| 5 | 점검중 | 운영불가 (A1) |
| 9 | 상태미확인 | 통신 오류 (A2·A3) |
| 0 | 알수없음 | 통신 오류 (A2·A3) |

### 2-3. 기본 정보 항목 (`master`)

| 항목 | 뜻 | 쓰임 |
|---|---|---|
| `statNm` | 충전소 이름 | 화면 표시, 검색 |

## 3. 제주데이터허브 862 (필수 데이터)

- **출처**: 제주데이터허브 「[인구, 생활] 전기자동차 충전소 정보」 (데이터 번호 862, 기준일 2025-09-21)
- **내려받기**: `hub_stations.py` (환경변수 `HUB_KEY` 필요, 저장소에는 키 없음)
- **규모**: 충전소 3,446곳

### 3-1. 항목

| 항목 | 뜻 | 쓰임 |
|---|---|---|
| `chargingPlace` | 충전소 이름 | 매칭 확인 |
| `startTime`, `endTime` | 운영 시작·종료 시각 | **열려 있던 시간만 세기** |
| `holiday` | 휴무 (`연중무휴`, 토·일 미개방 등) | **주말 휴무 보정**, 전용·출입제한 충전기 제외 |

| `baseDate` | 기준일 | `20250921` |

### 3-2. 허브 데이터가 진단을 바꾸는 3가지

1. **열린 시간 환산**: 오전 9시~오후 6시만 여는 충전소는 하루 24시간이 아니라 **9시간만** 이용 기회로 셉니다. 그래야 밤에 닫혀서 안 쓰인 것을 고장으로 오해하지 않습니다.
2. **주말 휴무 보정**: 토·일에 닫는 관공서 충전기는 주말 동안 '충전 중'이 이어져도 관용차 주말 주차로 보고, 토·일과 월요일 오전 9시 전에는 충전고착을 **경보로 올리지 않습니다**.
3. **전용 충전기 제외**: 휴무 칸에 '전용', '출입제한'이 적힌 충전소는 일반인이 못 쓰므로 숨은 고장 검사에서 뺍니다.

허브에 없는 충전소는 24시간 연중무휴로 가정합니다.

### 3-3. 1년 전(허브)과 지금 비교

허브(2025-09)의 운영기관별 충전기 수와 지금 수집한 충전기 수를 비교해, **1년 사이 사라진 충전기**를 보여 줍니다. AI 에이전트의 '1년 전(허브)과 비교' 질문이 이 계산을 씁니다.

## 5. 진단 결과 데이터 (파생)

`guardian/diagnose.py`가 2~3장 데이터로 충전기마다 아래 값을 만듭니다. 파일로 저장하지 않고 화면이 열릴 때 계산합니다(30분 캐시).

### 5-1. 주요 결과 항목

| 항목 | 뜻 |
|---|---|
| `code` | 판정 코드 (A1~A4, B1~B3, 없으면 정상) |
| `grade` | 등급: 경보 / 주의 / 관찰 |
| `why` | 근거 문장 (예: "같은 충전소 다른 3대는 평균 하루 3.3번 쓰이는데, 이 기기는 열려 있던 71일 동안 0번") |
| `방치_일` | A 판정은 그 상태가 이어진 일수, B 판정은 마지막 정상 충전 뒤 지난 일수 |
| `트랙` | 수리 / 행정(철거·목록 정리 검토) |
| `점수` | 점검 우선순위 (0~100) |
| `bundle` | 묶음 표시 (충전소 전체 동시 이상, 운영사 일괄 갱신) |
| `gate` | 판정 보류·제외 사유 |
| `p_hid`, `q_hid` | 숨은 고장 확률 값, BH 보정 값 |
| `lam`, `basis`, `n_ref` | 비교 집단의 하루 평균 이용 횟수, 비교 방식(형제/이웃), 비교 대수 |
| `alt` | 1km 안에서 정상 작동 중인 같은 종류 대체 충전기 수 |

### 5-2. 판정 규칙과 기준 숫자

| 코드 | 이름 | 주의 | 경보 | 기준 근거 |
|---|---|---|---|---|
| A1 | 운영불가 | 점검중 24시간 미만 | 운영중지, 또는 점검중 24시간 이상 | 공식 상태 |
| A2 | 통신두절 | 통신 오류 6시간 연속 | 24시간 연속 | 끊긴 시간이 길수록 등급을 올림 |
| A3 | 간헐통신 | — | 최근 48시간 수집 20번 이상 중 50% 이상 통신 오류 + 상태 2번 이상 바뀜 + 정상 충전 0건 | 붙었다 끊겼다 반복 |
| A4 | 충전고착 | 급속 4시간 / 완속 24시간 | 급속 48시간 / 완속 72시간 | 정상 충전의 99%가 급속 3.6시간, 완속 14.5시간 안에 끝남. 경보는 금요일 저녁~일요일 저녁 주차보다 길게 |
| B1 | 숨은고장(형제) | (관찰) 우연일 확률 1% 미만 | 우연일 확률 0.1% 미만 + BH 보정 5% 이하 | 같은 충전소 같은 종류 충전기와 비교 |
| B2 | 숨은고장(이웃) | (관찰) 〃 | 〃 | 같은 충전소에 비교 대상이 없을 때, 가까운 정상 충전기 30대(최대 10km, 최소 5대)와 비교 |
| B3 | 실패충전 반복 | — | 관측 충전 3번 이상, 그중 5분 미만 3번 이상, 우연일 확률 0.1% 미만 | 평소 5분 미만 충전 비율과 이항 검정 |

**숨은 고장 확률 계산 (B1·B2)**

- 비교 집단의 '열린 하루당 이용 횟수'를 구하고, 이 충전기가 **마지막 정상 충전 이후 열려 있던 시간** 동안 0번 쓰일 확률을 음이항 분포로 계산합니다.
- 충전기마다 원래 인기 차이가 있으므로 이질성을 반영합니다. 형제끼리는 0.16(±40% 차이 허용, 한전 실측 0.155)이고, 이웃은 데이터에서 추정하되 0.16 이상으로 둡니다.
- 비교 집단의 '정상'은 지금 사용 가능·충전 중이면서 7일 안에 정상 충전이 있었던 충전기입니다.
- 비교 집단 전체의 최근 24시간 이용이 평소의 절반 미만이면 (태풍·연휴 등) **판정을 보류**합니다.

**검사에서 빼는 충전기 (품질 게이트)**

- 이용자 제한(`limitYn = Y`)
- 허브에 전용·출입제한으로 적힌 충전소
- 충전 이력이 한 번도 없는 충전기 (신규·미사용)
- 삭제 표시(`delYn = Y`), 위치 없음

### 5-3. 묶음

- **충전소 전체 동시 이상**: 한 충전소의 충전기 2대 이상이 모두 경보이면 개별 고장보다 전원·통신 설비 1건으로 점검하도록 묶습니다.
- **운영사 일괄 갱신**: 같은 1분 안에 5곳 이상, 10대 이상의 운영불가·통신두절 상태가 한꺼번에 갱신되면 운영사 시스템 일괄 갱신으로 표시합니다. 이때 실제 고장 시작은 더 이를 수 있습니다.

### 5-4. 트랙과 우선순위 점수

- **행정 트랙**: A1~A3 경보이면서 1년(365일) 넘게 한 번도 쓰이지 않은 충전기입니다. 수리보다 철거·목록 정리를 검토할 대상입니다.
- **수리 트랙**: 그 밖의 판정 충전기이고, 아래 점수 순으로 점검합니다.

```
점수 = 확실도 × (0.2 + 하루 이용량) × (1 + log10(1 + 방치 일수, 최대 90일))
       × 대체 충전기 가중 (1km 안 정상 대체 충전기 0대 1.5 / 1~2대 1.2 / 3대 이상 1.0)
       × 급속 가중 1.3
→ 상위 1% 값을 100점으로 맞춤
```

- **확실도**는 A1 1.0, A2 0.9, A3 0.8, A4 0.7이고, B는 확률이 낮을수록 0.5~0.9입니다. 여기에 등급 가중(경보 1.0 / 주의 0.6 / 관찰 0.4)을 곱합니다.
- 즉 **많이 쓰이던 곳**, **오래 방치된 곳**, **근처에 대신 쓸 충전기가 없는 곳**, **급속**일수록 먼저 고칩니다.

**채점 기준 (고정 뒤 7일)**

| 결과 | 기준 |
|---|---|
| 적중-계속 멈춤 | 7일 동안 정상 충전 0회, 비교 대상(같은 충전소 같은 종류, 없으면 10km 안 가장 가까운 같은 종류 30대)은 1회 이상 |
| 적중-운영사 확인 | 기간 중 운영중지·점검중으로 바뀌거나 통신이상이 생김 |
| 오탐 | 고정 후 24시간 안에 상태 변화 없이 정상 충전 |
| 판단 보류 | 24시간 뒤 정상 충전(원격 수리인지 원래 정상인지 구분 불가), 비교 대상도 0회, 데이터 없음 |

- **적중률** = 적중 ÷ (적중 + 오탐). 판단 보류는 분모에서 빼고 개수를 따로 적습니다.
- **비교 정상 목록**: 같은 기준으로 세되 '계속 0회 / 고장 처리됨 / 정상 사용 / 판단 보류'로 부르고, '계속 0회' 비율을 숨은 고장 목록과 비교합니다.
- **수리 목록**: 7일 뒤 같은 문제로 계속 방치된 비율과 복구된 비율을 적습니다.

## 7. 품질과 한계

- **수집 간격**: 30분입니다. 30분보다 짧은 상태 변화는 놓칠 수 있습니다.
- **수집 공백**: 수집 초기(11/4~11/5)에 4~8시간 공백이 4번 있었습니다. 11/5 23:00 이후로는 30분 간격으로 끊김 없이 수집하고 있습니다.
- **추정이지 확정이 아닙니다**: 숨은 고장은 이용 기록으로 계산한 확률입니다. 일반차 주차, 공사, 주변 행사 등으로도 이용이 끊길 수 있어 화면마다 현장 확인 결과를 기록하게 했습니다.
- **API 값에 의존**: 운영사가 상태를 늦게 갱신하거나 한꺼번에 갱신하면 방치 일수가 실제와 다를 수 있습니다. 일괄 갱신은 묶음으로 따로 표시합니다.
- **허브 기준일**: 허브 862는 2025-09 기준이라 그 뒤 새로 생긴 충전소는 운영시간을 24시간으로 가정합니다.
- **개인정보 없음**: 충전기·충전소 단위 데이터만 쓰고, 이용자 정보는 없습니다.
